Mailer macros / tokens (Questall)
================================

This mailer supports "token" macros in the form:
  ##TOKEN##

Tokens are replaced by code in `index.js` (see `replaceTokens()`), and are applied to:
  - Email subject (from randomizer subject list or config subject)
  - From name (from randomizer sender names or config `message.from_name`)
  - Email HTML body (the chosen `LETTER/*.html` template)
  - Custom headers (`custom_headers`)
  - Attachment filenames (configured names / formats)
  - Attachment HTML content *when converting an HTML attachment to PDF*
  - QR links (the configured `html_qr_link` is token-expanded before generating QR)

Important: token replacement is simple string substitution; there is no conditional logic,
no loops, and no escaping beyond what your templates already contain.


Global attachment disable (no attachments at all)
-------------------------------------------------

You can disable **all** attachments (regular attachments, advanced attachments, auto-added images,
and auto-fetched logos) by setting any of the following:

  - `attachments_enabled: false` (top-level, recommended)
  - `attachments: { enabled: false }`
  - `Atatchimento.attach_file: false`


Core tokens (always available via `replaceTokens`)
--------------------------------------------------

##EMAIL##
  - Meaning: recipient email address
  - Where you can use it: subject, from name, letter HTML, headers, attachment filenames,
    attachment HTML content (pre-PDF), QR link
  - Example: "Hello ##EMAIL##"

##USER##
  - Meaning: derived from the recipient email local-part (before `@`), title-cased
    Examples:
      - "doe@example.com" -> "Doe"
      - "john.smith@example.com" -> "John"
      - "mary-jane@example.com" -> "Mary"
  - Where you can use it: same as ##EMAIL##
  - Example: "Hi ##USER##,"

##DOMAIN##
  - Meaning: recipient email domain (after `@`)
    Example: "doe@example.com" -> "example.com"
  - Where you can use it: same as ##EMAIL##
  - Example: "Domain: ##DOMAIN##"

##HEX_MAIL##
  - Meaning: recipient email encoded as hex (utf-8 bytes -> hex string)
  - Where you can use it: same as ##EMAIL##
  - Example: "https://example.com/u/##HEX_MAIL##"

##COMPANYNAME##
  - Meaning: inferred company name (first subdomain part of recipient domain)
    Example: "jane@acme.com" -> "acme"
  - Where you can use it: same as ##EMAIL##
  - Example: "Message From ##COMPANYNAME##"

##RANDFROMNAME## and ##FROMNAME##
  - Meaning: the selected sender display name for this email.
    If randomizer sender names are enabled, it’s the picked line from `SETTING/sender_names.txt`.
    Otherwise it comes from `SETTING/config.yml` -> `message.from_name`.
  - Where you can use it: subject, from name, letter HTML, headers, attachment filenames,
    attachment HTML content (pre-PDF), QR link
  - Example: "Regards, ##FROMNAME##"

##FAKE_COMPANY##
  - Meaning: a generated company-like name (e.g. "Apex Systems", "Silver Ventures")
  - Where you can use it: same as ##EMAIL##
  - Note: generated per token-replacement call; different strings (subject vs body vs attachment name)
    may get different fake companies.
  - Example: "##FAKE_COMPANY##"

##FAKE_COMPANY_EMAIL##
  - Meaning: a generated email address derived from the fake company and a fake full name
    (e.g. "alex.stone@apex-systems.com"). If a name isn’t available, it falls back to
    a generic local-part like "info".
  - Where you can use it: same as ##EMAIL##
  - Example: "Contact: ##FAKE_COMPANY_EMAIL##"

##FAKE_FULLNAME##
  - Meaning: a generated person name (e.g. "Alex Stone")
  - Where you can use it: same as ##EMAIL##
  - Example: "Regards, ##FAKE_FULLNAME##"

##NUMRANDOM3## / ##num3##
##NUMRANDOM4## / ##num4##
##NUMRANDOM5## / ##num5##
  - Meaning: random digits of the specified length (3, 4, or 5)
  - Where you can use it: same as ##EMAIL##
  - Example: "Ref: ##NUMRANDOM5##"

##NUMRANDOMn##
  - Meaning: random digits of length n
  - Where you can use it: same as ##EMAIL##
  - Example: "Code: ##NUMRANDOM12##"

##STRINGRANDOMn##
  - Meaning: random alphanumeric string of length n (A–Z, a–z, 0–9)
  - Where you can use it: same as ##EMAIL##
  - Example: "Token: ##STRINGRANDOM32##"

##{a|b|c}##
  - Meaning: random pick between the pipe-separated options inside the braces.
    The chosen option can itself contain other tokens (those will be processed afterward).
  - Where you can use it: same as ##EMAIL##
  - Example:
    - "Hello ##{friend|there|team}##"
    - "From ##{##COMPANYNAME##|##FAKE_COMPANY##}##"

##DATE##
  - Meaning: current date as MM/DD/YYYY (en-US locale)
  - Where you can use it: same as ##EMAIL##
  - Example: "Date: ##DATE##"

##TIME##
  - Meaning: current time as a locale 12-hour time string (e.g. "01:23 PM")
  - Where you can use it: same as ##EMAIL##
  - Example: "Time: ##TIME##"

##ISODATE##
  - Meaning: current date as YYYY-MM-DD
  - Where you can use it: same as ##EMAIL##
  - Example: "Generated: ##ISODATE##"

##YEAR##
##MONTH##
##DAY##
  - Meaning: components of the current date
    - YEAR: 4-digit year (e.g. 2026)
    - MONTH: 2-digit month (01-12)
    - DAY: 2-digit day (01-31)
  - Where you can use it: same as ##EMAIL##
  - Example: "##YEAR##-##MONTH##-##DAY##"


Special placeholders (handled outside `replaceTokens`)
------------------------------------------------------

##QRCODE##
  - Meaning: replaced with a generated QR code image as a data URL (PNG) when processing
    an HTML attachment for PDF conversion OR when explicitly embedding QR into HTML.
  - Where you can use it:
    - In attachment HTML files (e.g. `ATTACHMENT/*.html`) that are converted to PDF when
      `Atatchimento.html_option.html_attach_to_pdf: true`
    - Not a generic `replaceTokens` macro; it is only filled by the QR embed step.
  - Requirements:
    - `Retakontororu.image_setting.use_html_qr.html_qr_link` must be set (supports tokens).
  - Example:
    - `<img src="##QRCODE##" />`

##COMPANYLOGO##
  - Meaning: replaced with a fetched company logo (data URL) based on the recipient domain.
  - Where you can use it:
    - In attachment HTML content *only in the HTML->PDF attachment conversion pipeline*
      (it’s embedded during attachment preparation, not during normal email-body rendering).
  - Requirements:
    - `auto_fetch_company_logo: true`
    - The HTML attachment must be processed through the embed step (HTML->PDF conversion).
  - Example:
    - `<img src="##COMPANYLOGO##" />`

cid:company-logo-clearbit
  - Meaning: you can also use the literal `cid:company-logo-clearbit` in an attachment HTML
    file; during the same logo-embed step it will be replaced with the logo data URL.
  - Where you can use it: attachment HTML content (HTML->PDF conversion pipeline)
  - Example:
    - `<img src="cid:company-logo-clearbit" />`


Not implemented as a mailer token
---------------------------------

##USERLOGO##
  - Status: appears in templates/config comments but there is no token replacement for it
    in `index.js`, so it will remain literally "##USERLOGO##" in output unless you replace
    it yourself in the template or change the config to point at a real image filename.
  - Related config:
    - `Retakontororu.image_setting.use_html_qr.html_qr_logo_path` expects an image filename
      (looked up under `IMAGE/`) or an absolute path; it does not understand ##USERLOGO##.
